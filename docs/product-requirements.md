# JevNews 产品需求基线

> v0.4 · 2026-09-19 · 当前产品合同；实现和验证状态另见 [交付状态](implementation-status.md)。

## 1. 已确认产品方向

一个外观和阅读操作尽可能保持 Hacker News 原样、允许用户选择阅读标准的独立网页服务。不是新闻摘要器，也不另建投稿、投票和评论社区。

平台主动理解文章并承担费用；提供多套无需注册的公共预设；支持私人个性化，但必须注册。内容不局限于热门，不因低票而排除。暂不收费，不要求用户配置模型 Key。

“99% 相似”是方向，不是已经测得的完成率。保留紧凑文本列表、编号、标题、域名、HN 分数、元数据、评论树、普通链接和 More 翻页。不做卡片流、大图、聊天式首页、侧边栏或无限滚动。自有 J 标识和账号说明不能假冒 HN 官方。

## 2. 第一版内容范围

来源仅限 HN。普通外链、文本帖、Ask HN、Show HN、投票帖参与发现；招聘保留 HN 阅读入口，默认不参与 AI 排序。分析可取得的正文、投稿文本或项目说明，不执行项目、审计全库或绕过访问限制。

评论可以树状阅读、折叠、按分支加载；第一版不做整棵评论树的 AI 总结或重排。PDF、音视频、登录墙、强 JavaScript 页面不承诺全文分析，失败或不完整必须标注。

个性化候选默认最近 7 天，运行安全上限 10,000 条；达到上限显示覆盖限制，不能宣称已经完整分析所有内容。原始 HN 模式保留官方列表顺序。初次回填、运行积压和失败缺口分别记录；最早发现时间不等于连续完整覆盖。

## 3. 公共文章画像

| 分析组 | 当前结构 |
| --- | --- |
| 主题 | AI、数据库、系统、工程、安全、硬件、科学、数学、设计、产品、创业、历史、其他，多标签概率 |
| 内容形态 | 教程、解释、经验、复盘、测量、研究、项目、发布、消息、随笔、提问 |
| 解释深度 | 结论/介绍 → 具体说明 → 步骤机制 → 约束和取舍的等级 |
| 证据和经验 | 是否有案例、方法、测量条件、引用，以及作者一手工作描述 |
| 门槛与目的 | 阅读背景需求、推广目的；推广不自动等于无价值 |
| 来源范围 | extracted、truncated、metadata，内容版本、模型、rubric 版本 |
| 重复 | 当前以正文哈希或相同 URL 处理重复；不承诺用户全部已读历史的语义信息增量判断 |

Jev 产生结构化判断；程序处理正文抽取、去重、排序和展示。发现“有实验材料”不等于验证其真实性，不展示通用的“文章质量 87 分”。没有正文不能装作读过全文。

当前实现显示形态与有限/截断标签。精确的句子级证据定位和解释展开仍属于后续增强；不应在界面伪造原文引用。原文用于内部分析，本站不提供全文镜像。

## 4. 七套公共预设

| ID | 名称 | 标准 |
| --- | --- | --- |
| balanced | Balanced | 跨主题解释、经验、证据和好奇心，避免单一话题连续霸榜 |
| engineering | Engineering | 实现、部署、故障、测量与取舍 |
| ai-builders | AI & Agents | AI/Agent 的构建、评估、运行和失败经验 |
| systems | Systems & Databases | 数据库、存储、操作系统、网络与内部机制 |
| builders | Show & Build | 具体项目、小工具、低曝光实验，不要求已经热门 |
| startups | Products & Startups | 产品、定价、用户、商业模式和一手创业经验，不只看公告 |
| curiosity | Curiosity | 科学、数学、硬件、历史与设计，不要求贴近工作 |

默认 Balanced，公共预设单选、免登录。主题、类型、深度、证据、新鲜度和小幅社区信号由程序组合。低票不是准入门槛。当前公式是可测试起点，未声称已经完成真实用户效果评估。

排序、精选和标注共存。picks 是分析充分且达到当前阈值的子集，不凑固定篇数；all 保留更多选择。HN points 不替换为 Jev 分数。

## 5. 私人规则

注册后从公共预设复制或填写自然语言要求。编译结果必须先展示、校验、保存才能应用，不因一次点击暗中改变长期标准。无法执行的要求必须列入 unsupported，确认后才能应用其余部分。

第一版 DSL 支持主题权重、内容类型偏好/降权、域名排除、AND/OR/NOT 组合条件、软规则例外和最多三个专项语义条件。硬条件遇到未知不当作匹配；例外不能自动越过硬排除。

| 参数 | 起点 |
| --- | --- |
| 私人规则 | 每账号 3 套 |
| 专项条件 | 每套最多 3 个 |
| 专项评估 | 每账号每日 100 篇文章版本评估组上限；缓存命中复用 |
| 创建/修改 | 每账号每日 20 次 |
| 全站规则编译 | 默认每日 100 次调用上限，不等于 Neurons 用量保证 |
| 候选复判 | 激活并访问的规则中，先筛选最多 100 个相关、具备正文分析的候选 |

专项要求只对实际评估过的候选给出判断。重试可能额外占用计数；按供应商实际 token 用量独立记账。达到预算后已有阅读和已计算结果可继续使用，新工作延迟而不是静默放松要求。

当前规则审阅以自然语言原文和可编辑 JSON 展示。非技术用户友好的可视化规则解释器尚未完成，不把当前编辑器包装成最终交互。

## 6. 账号与 HN 行为边界

本站使用用户名、密码和一次性恢复码；没有连接邮件服务前不承诺邮件找回。密码使用 scrypt，不保存明文。注册只创建 JevNews 身份，不接受 HN 密码、Cookie 或冒充官方登录。

HN 数据阅读在本站；投票、回复、提交、举报等实际写动作回 HN。past、全站 comments 等未精确实现的视图明确跳回原站。投票帖目前只保证基础文本/讨论入口；完整选项显示仍需补齐。

hide、save 是 JevNews 状态：匿名存浏览器，登录存账号。切换私人规则不改变 HN 票数。账户可删除。公共预设当前记在浏览器；跨设备“最后选择预设”尚未实现，不能与私人规则已持久保存混为一谈。

## 7. 阅读稳定与异常

每页 30 条，More 使用同一不可变排序快照。后台更新只提示，不跳位。删除/死帖采用最新已知状态覆盖旧快照。快照过期返回显式提示，不偷偷切到新顺序。

同步时钟、分析时钟、阅读快照时钟独立。DO 默认约 60 秒发现，可配置约 10 秒；实际延迟包括执行、队列、上游和模型，不保证精确周期。上游不可用保留已有快照；分析失败或未配置保留 pending/limited，不填伪分数。

## 8. 技术与成本合同

Cloudflare 优先：一个 Worker 部署，模块划分为网页、同步、任务和 DO；D1、私有 R2、Queues、Turnstile，Workers AI 仅作规则编译。正式完整服务建议 Workers Paid，平台模型调用另计；免费对读者不等于无限资源。

默认关闭同步、Jev 调用和规则编译，必须运营者显式配置并启用。数据库迁移、资源创建、域名购买、远程部署均不是本次代码提交已经执行的操作。

## 9. 验收与未完成项

验收关注低票可发现、七预设差异、规则可解释执行、跨账号隔离、真实来源展示、稳定翻页、内容哈希复用、失败恢复、安全输入和实际成本。

当前结果见 [implementation-status.md](implementation-status.md)。后续发布验证包括真实 HN 负载、模型 schema/质量/用量、像素与交互对照、完整投票展示、更友好的规则编辑、来源证据定位、生产安全和数据删除演练。它们是明确待验证/待完成项，不是已经上线的能力。
