## 1. 产品定位

**一个外观和阅读操作尽可能保持 Hacker News 原样，但允许用户选择阅读标准的独立网页服务。**

JevNews 不只是新闻摘要工具，也不另建一个与 HN 分离的投稿、投票和评论社区。内容来自 HN，平台主动分析内容并承担费用；用户选择公共预设，或注册后建立自己的私人阅读标准。精选、排序和轻量高亮在同一份列表中工作。

用户表达的不只是主题关键词，还包括内容形态、实现细节、经验与证据、难度、偏好和例外。排序表示当前阅读优先级，不宣称为文章提供客观、通用的质量结论。

## 2. 决策状态与已确认要求

用户确认是硬约束；受托决定是用户授权制定的第一版设计；运行默认值可通过配置和实测调整；接口约束必须显式说明，不能用假按钮模拟 HN 成功操作。

| 编号 | 状态 | 需求 |
| --- | --- | --- |
| C-01 | 用户确认 | 平台主动理解支持范围内的文章，不要求用户逐篇触发。 |
| C-02 | 用户确认 | 平台承担默认文章理解费用，公共体验不要求 BYOK。 |
| C-03 | 用户确认 | 提供 N 套预定义个性化阅读方案。 |
| C-04 | 用户确认 | 用户可以选择预定义方案，不必从零创建规则。 |
| C-05 | 用户确认 | 支持私人个性化。 |
| C-06 | 用户确认 | 私人个性化必须注册。 |
| C-07 | 用户确认 | 不局限热门，不以高票数或首页曝光作为分析前提。 |
| C-08 | 用户确认 | 产品是独立网页，不以浏览器插件为第一版形态。 |
| C-09 | 用户确认 | 除新功能外，页面和行为以与 HN 99% 相似为目标，不做现代化改版。 |
| C-10 | 用户确认 | 暂时不收费，开放注册；不是永久免费或无限资源承诺。 |
| C-11 | 用户确认 | 必要时可以使用和维护数据库。 |

| P-01 | 受托决定 | 公共文章画像采用第 4 节定义。 |
| P-02 | 受托决定 | 七套公共预设，默认 Balanced。 |
| P-03 | 受托决定 | 私人个性化采用公共分析复用加有限专项判断。 |

| T-02 | 本轮技术设计 | 分钟级发现、异步分析与共享快照，替代十秒轮询起点；不是改变 HN 风格阅读。 |

“99%”是设计方向，当前没有测量像素或行为覆盖率。免费资源优先不意味着必须牺牲密码安全、内容覆盖或伪造能力来保持 $0。完整功能在 Free 额度不能安全稳定运行时，评估低成本升级，不自动开通收费服务。

## 3. 内容池和第一版范围

默认来源仅限 Hacker News。持续发现新的顶层投稿，包括普通外链文章、文本帖、Ask HN、Show HN 和投票帖；热门榜单是补充，不是唯一入口。招聘用于保持 jobs 和原始浏览，默认不进入七套阅读预设的 AI 排序。

有效新投稿均有资格进入平台处理流程。允许为当前访问内容安排即时优先级，但低票内容不能长期饥饿。死帖、删除帖、相同版本的重复任务不反复分析。额度不足时显示积压和覆盖，不宣称已经分析全部。

| 对象 | 第一版阅读能力 | 第一版 AI 分析 |
| --- | --- | --- |
| 外链文章 | 标题去原站；保留 HN 讨论入口 | 可获取的主要正文。 |
| 文本帖、Ask HN | 本地显示投稿和评论树 | 投稿文本；缺少代码不自动等于内容差。 |
| Show HN、项目主页 | 项目链接和 HN 讨论 | 项目说明/README；不承诺运行项目或审计全部代码。 |
| 评论 | 树状阅读、折叠、永久链接和回 HN | 不做全评论树摘要、AI 排序或争论结论判断。 |
| 招聘、投票 | 尽可能保留原站阅读语义，写操作回 HN | 招聘不进入预设排序；不生成或修改选项和票数。 |
| PDF、音视频、登录墙等 | 保留帖子浏览和跳转 | 不承诺 OCR、转写、多模态解析或绕过限制；如实标注覆盖。 |

个性化默认使用最近 7 天已发现的有效投稿，按 HN 投稿时间计算新鲜度，不把重新投稿说成原文首次发表。原始 HN 浏览不受这一候选窗口限制。

首次部署先加载当前官方列表，再限速回填；补齐前显示实际覆盖起点。第一版不理解整个 HN 历史全文。已发现不等于已完成正文理解。

## 4. 公共文章画像

原始来源、公共判断、用户规则与最终排序分开保存。画像版本化，供所有预设和私人规则复用。

| 分析组 | 产出和边界 |
| --- | --- |
| 主题 | AI/Agent、数据库、系统、软件工程、安全、硬件、科学、数学、设计、产品、创业、历史等多标签；实体需有可靠依据。 |
| 内容形态 | 教程、原理解释、工程经验、故障复盘、基准实验、研究、项目介绍、产品发布、行业消息、随笔、提问。类型不是好坏。 |
| 实现与解释深度 | 从介绍/结论，到步骤、机制、约束和取舍的描述等级；不把长文、术语或代码块数量等同于深入。 |
| 经验与证据 | 实际操作描述、实验方法、测量条件、日志、案例、引用。存在这些材料不等于已验证结论和数据真实。 |
| 阅读门槛 | 入门、需要背景、专业深入；长度等可直接计算。专业文章不自动优先。 |
| 内容目的 | 解释、经验分享、展示、推广、融资/商业消息、预测，允许混合；不一刀切排除公司博客。 |
| 可识别重复 | URL 规范化、正文哈希、同文重复投稿；不声称实现基于全部已读历史的信息增量判断。 |
| 可用性和来源 | 完整/部分/失败、分析范围、时间、内容与分析版本、可回查片段或引用。未知不是否。 |

文本抽取、实体处理、片段定位和自然语言规则编译可以使用程序或独立模块；不把它们全部当作 Jev 自带的自由文本生成能力。证据优先引用原文，不生成无法核对的引文。

默认不显示 0–100“质量分”，使用少量标签和模板化依据。HN 票数、评论数或排名变化，不触发未变正文的重新分析。

## 5. 七套公共预设

无需注册即可切换；第一版单选。首次默认 Balanced，之后记住选择。匿名保存在浏览器，注册用户可同步到账户。这些是产品设计，不宣称是 HN 用户调查分类。

| ID / 名称 | 阅读标准 | 例外 |
| --- | --- | --- |
| balanced / Balanced | 跨主题寻找有解释、经验、证据或独特观察的内容，控制重复和单一话题占比 | 不用技术深度评价所有科学、历史、设计和生活观察。 |
| engineering / Engineering | 部署、故障复盘、性能改进、架构取舍、有实现过程的经验 | 不要求大厂、大流量或重大事故。 |
| ai-builders / AI & Agents | AI/Agent 实现、评估、工具、失败案例、成本和运行经验 | 提供方法/实验的模型发布同样可以优先。 |
| systems / Systems & Databases | 数据库、存储、分布式、操作系统、网络的原理、实现和测量 | 好的解释型文章不需要附带事故或开源项目。 |
| builders / Show & Build | 具体可查看或尝试的项目、工具、新奇实现，覆盖低热度 | 不限 Show HN 标题；不开源不等于无价值；未运行不标已验证。 |
| startups / Products & Startups | 产品构建、用户研究、商业模式、定价、获客、一手创业经验 | 不排斥所有融资，只降低纯金额、口号和宣传的优先级。 |
| curiosity / Curiosity | 科学、数学、硬件、历史、设计等有解释和独特观察的内容 | 不要求与工作或软件工程有关。 |

每套显示简短标准并版本化。私人复制后保留当时版本，不随公共预设升级静默改变。

## 6. 私人个性化

注册后从预设复制或从零输入自然语言；展示原始要求和可执行规则，用户保存才生效。支持修改、重置、删除，默认私人，不进入公共市场。不因点击、停留或隐藏一次内容自动改变长期规则；已访问不等于读完。

公共维度能满足时直接重排。特殊要求对有限候选追加判断，例如“不依赖 Redis 且正文解释了恢复机制”；明确标记评估覆盖。不能判断则 unknown，不支持则 unsupported，不能假装执行成功。

用户要求必须满足的硬条件时，匹配列表只纳入证据充分的结果，提供未知/未评估数量及入口；不静默放松条件。第一版不支持无限网络研究、私库访问、代码执行、全历史回溯或开放式代理工作流。

| 运行项 | 起点 |
| --- | --- |
| 每账号私人规则 | 最多 3 套，同时使用 1 套。 |
| 每套专项语义条件 | 最多 3 个，普通主题偏好不因此都成为专项任务。 |
| 专项复判 | 每账号每日最多 100 篇文章版本评估组；每组最多 3 条件；新规则版本重新核算，缓存命中不重复消耗。 |
| 编译 | 每账号每日最多 20 次；浏览、预设切换和缓存读取不计入。 |
| 全站预算 | 单独限制 token、任务、并发、D1 和 Queues；个人上限不是全站即时吞吐保证。 |

达到限额保留基础阅读和已有结果，显示未执行部分，不出现支付引导。用户可主动回基础排序，系统不能默默修改硬条件。Cloudflare 免费档的全站处理池与运行频率见技术设计。

## 7. 第一版阅读界面

以橙色顶部、浅色背景、紧凑文本列表、编号、小箭头、标题与域名、灰色元信息、评论树、普通链接和 More 翻页为基线。默认英文 UI 和原文标题，不默认翻译或改写。自有 JevNews 品牌和独立服务说明必须保留。[S2]

不增加卡片流、大封面、仪表盘、侧边栏、聊天式首页或无限滚动。

导航下只增加紧凑控制：

`view: HN | Jev   preset: Balanced ▾   all | picks   my rules`

首次首页 Jev/Balanced，可切 HN 官方接口提供的列表顺序，不用自制热度公式冒充 HN 排名。关闭标注时，不用长摘要撑高列表。每篇常驻至多少量短标签，原因按需展开；points 和评论数始终属于 HN。

all 是该视图的候选列表，More 继续翻页；picks 是较高匹配且分析充分的子集，不凑固定篇数。排序考虑匹配、形态、新鲜度和有限社区信号，同文与多样性处理；探索不覆盖明确排除规则。

同轮浏览和 More 使用稳定快照；后台更新仅提示，不自动跳位。已知删除状态覆盖旧快照。快照过期明确刷新，不混合新旧分页。

## 8. HN 行为与账号边界

官方 API 不提供 HN 登录、投票、投稿或回复的正式写接口；也不能只靠公开时间和票数精确重建全部排名。[S1][S2]

| 操作 | 第一版 |
| --- | --- |
| 外链标题 | 去原网站，保留普通点击、新标签打开语义。 |
| 评论数、时间、文本帖 | 本地读取投稿和评论，保留原 HN 永久链接。 |
| 评论树 | 按 API kids 顺序，支持折叠，不自行重排或编造分数。 |
| 作者 | HN 公共资料或跳原页，与本站账户分开。 |
| hide、收藏、预设、规则 | 本站状态，不写回 HN；匿名可保存本地，注册后保存账户。 |
| upvote、reply、submit、flag、投票 | 回 HN 完成，入口说明；不代投票、不本地假成功。 |
| login/register | 本站用户名密码注册登录，不创建 HN 账号，不收集 HN 凭据。 |
| past、全站 comments、未精确支持页 | 保留入口，必要时明确跳 HN，不冒充精确历史或权限视图。 |
| 搜索 | 保留 HN Search 跳转，不作为实时数据权威来源。 |

认证采用成熟密码算法和安全会话。免费 CPU 若不能安全执行，就评估升级或另行确认认证变更，不自动改成只支持 GitHub OAuth。邮箱找回须在发信服务真正启用后提供；未启用时不得声称邮箱已验证或可找回，可提供高熵恢复码。本站账户和数据支持删除。

若将来要求本站直接完成 HN 真实写操作，需单独验证授权及写入方式，作为独立变更。

## 9. 同步与异常体验

当前采用 **HN 官方 API → Cloudflare 后台共享增量同步 → D1/R2 → 网页**。API 是来源，同步是使用方式，不是二选一。

本轮将部分端点十秒轮询调整为每分钟发现；不同列表 1–10 分钟更新，评论按需，公共 Jev 快照按脏数据合并发布，起点约 10 分钟，资源压力下明确降频。准确运行参数与免费约束见技术设计，不是对外 SLA。

| 状态 | 行为 |
| --- | --- |
| 只有元数据、待抓取/分析 | 原始浏览可见，Jev 视图明确待分析，不按零分判差。 |
| 只有标题或部分正文 | 说明分析范围，不说读过全文。 |
| 上游暂不可用 | 最近成功数据、更新时间和 HN 链接，退避重试。 |
| 规则失败、AI/计算额度不足 | 保留有效规则与已有结果，显示未执行部分。 |
| D1/Workers 等额度耗尽 | 根据实际可用组件降级，必要时静态故障页和原站链接；不承诺动态页面和登录继续可用。 |
| 正文或规则更新 | 新版本异步生成，不给旧结果套新标签。 |
| deleted/dead | 优先传播、清理或隐藏相关公开片段，不从旧快照复活。 |
| 新结果到达 | 提示更新，保留当前顺序、位置及分页。 |

HN 元数据更新时间、全文分析时间、排序生成时间分别记录。页面不因后台一分钟检查就一分钟跳动，也不承诺一分钟内完成 AI 理解。

## 10. 存储、Cloudflare 与成本

使用 D1 保存 HN 小型缓存、画像、预设、私人规则、账户、任务、游标与预算；R2 Standard 保存内部正文、快照与加密导出。不再把自建 PostgreSQL 当成第一版默认。无需向量库、图数据库、Redis、Kafka 或搜索集群。

先使用 Cloudflare 免费托管子域名；独立域名仍需购买，不能把免费 DNS 等同免费注册。免费 CPU、D1 行读写和消息配额都有硬边界。资源定价核验和升级条件见技术设计；当前没有开通付费资源。

正文仅供内部理解，不做原文镜像站。起始保留约 30 天正文、90 天元数据/画像、短期按需评论和排序快照；明确删除优先于正常保留期限。失去证据原文后不声称仍可展示它。

任务持久化、幂等、重试、租约；页面打开不重复跑全站分析。公共分析跨用户共享，私人数据按账户隔离。暂时不收费，无默认 BYOK；平台免费不等于 Jev 调用免费，也不意味着所有功能无限计算。

## 11. 第一版不做

不另建投稿/评论社区或本地票数体系；不托管 HN 凭据；不承诺官方写操作无跳转。

不做全文翻译、长摘要、文章聊天、全评论树 AI 分析、基于全部已读历史的语义去重、规则市场、隐式兴趣学习、原生 App、默认 BYOK 或收费套餐。

这些不阻塞第一版核心：HN 原样阅读、七套共享预设、注册后的私人规则。

## 12. 验收

| 编号 | 要点 |
| --- | --- |
| A-01 | 固定样本比对桌面/移动列表、详情、评论、用户页和账号表单，单列新增控件及必要差异。 |
| A-02 | 低票新帖无需热门曝光即可被发现、排队、进入候选；监测饥饿和覆盖。 |
| A-03 | 七套预设具版本化标准、正反例和例外，有样本验证而非七份相同列表。 |
| A-04 | 公共无需注册，私人必须认证，跨账户读写与快照访问被拒绝。 |
| A-05 | unknown、unsupported、超额、未覆盖可见，不假装执行。 |
| A-06 | HN 数据与匹配标签分开，真实写操作不显示假成功。 |
| A-07 | More、刷新和返回稳定；已知删除覆盖旧快照。 |
| A-08 | 未变化正文不因分数/评论变化重跑 AI；缓存可核查。 |
| A-09 | 中断、重复、过期任务、删除与恢复可测试。 |
| A-10 | HTML、URL、正文和规则有安全边界，不能执行应用命令、泄露 Secret 或改变权限。 |
| A-11 | 记录真实 token、成本、覆盖、同步滞后与判断误差，不只看点击率。 |
